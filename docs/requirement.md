**Chef Passport（仮称）** — 日本人シェフの経歴・スキルを入力すると、AIが「どの国の、どの厨房で、どのビザで通用するか」を提示するクロスボーダー・マッチングPoC。CHEFLINK GLOBALが「型が見えたらプロダクト化」の段階であることへの先回り実装。彼らの掲げる「ボーダレス就労インフラ」の最初の1ピースを形にする。

### このテーマを選んだ根拠

- スキル可視化・信頼の非対称・需給の波は**既にCHEFLINK本体が解決済み**（AIプロフィール自動生成、Trust Data、正社員採用支援）。焼き直しは避ける
- 未解決フロンティアは4つ：地方展開 / GLOBALプロダクト化 / Trust Data深化 / 経営支援。GLOBALは**彼ら自身が「探っているフェーズ」と認める領域**で、外部からの提案が最も効く
- カジュアル面談で「海外展開における各国規制への対応課題」を質問済み。「あの時気になった領域を、自分でプロトタイプを作って考えてきました」という導入トークが成立する
- 根拠ソース：[CHEFLINK季刊レポート2026年冬号](https://sharedine.co.jp/news/20260226/)（英語版LP公開）、[CHEFLINK GLOBAL](https://cheflink-global.com/)

## デモ体験フロー（3画面）

### 画面1：シェフ選択

プリセット3人のカードを並べ、**面接官自身に選んでもらう**。デモが一方的な映像ではなく対話になる。右上に「自由入力モード」ボタン（奥の手）。

| ペルソナ（仮名） | ジャンル | 経歴 | 武器 | 語学 | 演出意図 |
| --- | --- | --- | --- | --- | --- |
| 佐藤 匠 | 寿司・割烹 | 銀座の割烹で8年 | 白身の捌き、柳刃、おまかせ構成 | 日常会話レベル | シンガポール◎（EP基準クリア）、アメリカ△（O-1は実績次第） |
| 鈴木 遥 | フレンチ | 恵比寿のビストロで5年 | ソース仕立て、低温調理 | 簡単な英会話 | オーストラリア○（482スポンサー）などバランス型 |
| 高橋 健太 | ラーメン | 家系ラーメン店で6年 | 大量スープ仕込み、店舗オペ全般 | ほぼ不可 | 語学要件で判定が大きく変わる例。ワーキングホリデーの提示も |

3人で結果が明確に分岐する設計にし、「固定出力のプロンプトデモ」ではなく**汎用的な仕組み**であることを証明する。

### 画面2：AI処理の可視化

密かな主役。以下の4ステップをリアルタイム表示し、「AIに何をやらせるかの設計力」を画面そのもので語る。実際の処理ログを流す。

1. スキルを抽出・構造化しています
2. 国別のビザ要件と照合しています
3. スキル表現を現地の厨房用語に変換しています
4. 海外求人とマッチング・スコアリングしています

### 画面3：結果ダッシュボード（本作り込みの主役・全工数の4割）

- **国カード**：3カ国それぞれに適合度（◎○△）＋理由。地図演出は時間があれば
- **ビザ要件の要約**：主要就労ビザ1〜2種の要件（年収基準・経験年数・スポンサー要否・滞在期間）と「このシェフのクリア状況」
- **スキルの現地語翻訳**：「柳刃で白身を引ける」→ 英語の等価スキル表現。日本の職人スキルが世界の共通言語になる瞬間を見せる
- **求人マッチリスト**：15件のモック求人から上位3〜5件をスコア＋理由文つきで提示
- 全画面に**「※デモ用モックデータです」**を明記（法的リスクの遮断）

## データ仕様

### 対象国とビザ（3カ国×1〜2種）

| 国 | 主要ビザ | 制度の型 |
| --- | --- | --- |
| シンガポール | Employment Pass（COMPASS点数制・最低給与基準）／S Pass | 点数制・給与基準 |
| オーストラリア | Skills in Demand visa（subclass 482）／Working Holiday（417、〜30歳） | スポンサー制 |
| アメリカ | H-2B（一時・季節労働）／O-1（卓越能力） | 抽選・実績証明型 |

制度の型が三者三様なので、「国ごとの違いをAIが構造化して扱える」ことが最も見せやすい組み合わせ。外務省統計で日本食レストラン数の多い市場でもある。

### 構造化スキーマ（例）

```json
{
  "country": "Singapore",
  "visas": [
    {
      "name": "Employment Pass",
      "minSalarySGD": 5000,
      "requiresSponsor": true,
      "duration": "2年（更新可）",
      "notes": "COMPASS点数制。給与・学歴・国籍多様性等で採点"
    }
  ]
}
```

### モック求人（各国5件＝15件）

項目：店舗タイプ・都市・給与レンジ・必要スキル・ビザスポンサー可否。実在の店名は使わず「Singapore CBDの高級寿司店」「シドニーのホテル和食部門」「LAのラーメン店」等のモック表現。

## AIパイプライン設計（Claude API）

1. **スキル抽出・構造化**：経歴テキスト → 構造化スキルセット（structured output）
2. **国×ビザ適合判定**：構造化スキル × ビザ要件データの照合 → 適合度＋判定理由
3. **スキル翻訳**：日本の厨房用語 → 現地の等価スキル表現
4. **求人マッチング**：15件にスコア＋理由文生成

キャッシュ戦略：プリセット3人分は上記パイプラインの出力を事前生成して静的キャッシュ（再現性100%）。自由入力のみライブAPI。タイムアウト・エラー時はプリセット表示にフォールバック。

## やらないこと（スコープ外）

- 海外事業者側の体験（彼らが手探り中の領域への口出し回避）
- 4カ国目以降の追加
- 実在レストラン・実在求人の使用
- ログイン・DB・求人管理機能
- ビザ情報の法的正確性の保証（「構造化できることの実証」が目的）

## 面接での見せ方（デモスクリプト）

1. **導入30秒**：「カジュアル面談で、GLOBALは型が見えたらプロダクト化と伺って気になっていた領域です。自分でプロトタイプを作って考えてきました」
2. 面接官にプリセットシェフを選んでもらう → 画面2・3を実演
3. 「実は自由入力もできます」→ ライブAPIで畳みかける（失敗してもプリセットに退避）
4. 設計の語り：パイプライン4ステップ、キャッシュ戦略、構造化出力、なぜClaudeか
5. 締めの提言：「本番化するなら、エージェント業務のワークフローから逆算してデータソースをCMS化するところから」と議論を投げる

## リスクと対策

| リスク | 対策 |
| --- | --- |
| 社内で既に同様の検討がある | むしろ議論の叩き台に。「社内の検討と重なっていたらぜひ教えてください」で会話を深める |
| ビザ情報の不正確さを指摘される | 免責明記＋「構造化の実証が目的」と前置き。出典リンクを画面内に |

| 25時間超過 | 下記の削る優先順位を適用 |
