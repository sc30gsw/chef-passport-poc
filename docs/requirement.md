### このテーマを選んだ根拠

- スキル可視化・信頼の非対称・需給の波は**既にCHEFLINK本体が解決済み**（AIプロフィール自動生成、Trust Data、正社員採用支援）。焼き直しは避ける
- 未解決フロンティアは4つ：地方展開 / GLOBALプロダクト化 / Trust Data深化 / 経営支援。GLOBALは**彼ら自身が「探っているフェーズ」と認める領域**で、外部からの提案が最も効く
- カジュアル面談で「海外展開における各国規制への対応課題」を質問済み。「あの時気になった領域を、自分でプロトタイプを作って考えてきました」という導入トークが成立する
- 根拠ソース：[CHEFLINK季刊レポート2026年冬号](https://sharedine.co.jp/news/20260226/)（英語版LP公開）、[CHEFLINK GLOBAL](https://cheflink-global.com/)

この期待結果表は**テスト仕様**として `src/domain/__tests__/expected-outcomes.test.ts` に直接アサートする。表を固定し、ビザ要件と求人の数値を表を満たすよう逆算調整する（→ PLAN.md §3.3）。

密かな主役。以下の4ステップをリアルタイム表示し、「AIに何をやらせるかの設計力」を画面そのもので語る。実際の処理ログを流す。

### 画面3：結果ダッシュボード（本作り込みの主役・全工数の4割）

- **国カード**：3カ国それぞれに適合度（◎○△）＋理由。地図演出は時間があれば
- **ビザ要件の要約**：主要就労ビザ1〜2種の要件（年収基準・経験年数・スポンサー要否・滞在期間）と「このシェフのクリア状況」
- **スキルの現地語翻訳**：「柳刃で白身を引ける」→ 英語の等価スキル表現。日本の職人スキルが世界の共通言語になる瞬間を見せる

## データ仕様

### 対象国とビザ（3カ国×2種＝6種）

| 国             | 主要ビザ                                                              | 制度の型         |
| -------------- | --------------------------------------------------------------------- | ---------------- |
| シンガポール   | Employment Pass（COMPASS点数制・最低給与基準）／S Pass                | 点数制・給与基準 |
| オーストラリア | Skills in Demand visa（subclass 482）／Working Holiday（417、〜30歳） | スポンサー制     |
| アメリカ       | H-2B（一時・季節労働）／O-1（卓越能力）                               | 抽選・実績証明型 |

制度の型が三者三様なので、「国ごとの違いをAIが構造化して扱える」ことが最も見せやすい組み合わせ。外務省統計で日本食レストラン数の多い市場でもある。

### 構造化スキーマ（例）

スキーマは `effect/Schema` で定義し、型はそこから導出する（型と検証を二重に書かない）。決定論的な関数が比較する値は `Schema.Literal` の union にする。

```json
{
  "country": "SG",
  "name": "Employment Pass",
  "sourceUrl": "https://www.mom.gov.sg/...",
  "requiresSponsor": true,
  "minSalary": { "amount": 5000, "currency": "SGD", "period": "month" },
  "minExperienceYears": 3,
  "expectedLanguage": "conversational",
  "requiresEvidenceProof": false,
  "durationNote": "2年（更新可）。COMPASS点数制"
}
```

`maxAgeYears` は417のみ、`requiresEvidenceProof` はO-1のみ true。数値はモックだが `sourceUrl` は**実在の政府ページ**（MOM / Department of Home Affairs / USCIS）を使い、各数値に出典と取得日のコメントを付ける。URLは実装時に取得し、推測で書かない。

求人の `requiredSkills` とペルソナのスキルは `src/data/skill-vocabulary.json` の**同一語彙表**を引く。文字列一致が成立することが決定論スコアの前提で、どちらかが自由記述だと全マッチが静かに0点になる。

### モック求人（各国5件＝15件）

項目：店舗タイプ・都市・給与レンジ・必要スキル・必要経験年数・要求語学レベル・ビザスポンサー可否。実在の店名は使わず「Singapore CBDの高級寿司店」「シドニーのホテル和食部門」「LAのラーメン店」等のモック表現。

**意図的な配分**（各国5件）：スポンサー可4件＋**不可1件**（除外パスを必ず発火させる）、要求語学は `business` 2件 / `conversational` 2件 / `basic` 1件（高橋が語学で落ちることが目に見える）。

## AIパイプライン設計（決定論 / LLM の境界）

**判断は決定論、言語化だけがLLM。** これがこのPoCの中心的な設計主張であり、テストが証明する対象。スコアリングや適合判定をプロンプトに移すことは**しない**。

| ステップ                                         | 実装                                              | 置き場所                                              |
| ------------------------------------------------ | ------------------------------------------------- | ----------------------------------------------------- |
| 1. スキル抽出・構造化                            | **LLM** — `generateObject`（`SkillSet` スキーマ） | `src/features/passport/api/steps/extract-skills.ts`   |
| 2. 国×ビザ適合判定                               | **決定論的な純関数**＋説明文のみLLM               | `src/domain/visa-eligibility.ts`                      |
| 3. スキル翻訳（日本の厨房用語 → 現地の等価表現） | **LLM** — `generateObject`                        | `src/features/passport/api/steps/translate-skills.ts` |
| 4. 求人マッチング（15件）                        | **決定論的スコア**＋理由文のみLLM                 | `src/domain/scoring.ts`                               |

ハード制約（スポンサー不可・年齢超過・給与下限未達・実績証明の不足）は**減点ではなく除外**し、除外理由をUIに表示する。それがロジックの存在を目に見える形で証明する。

**モデルと経路**：Vercel AI Gateway 経由（Anthropic互換 `/v1/messages`）。抽出・翻訳は `anthropic/claude-haiku-4.5`、説明文は `anthropic/claude-sonnet-5`。モデルスラッグはプロバイダ接頭辞が必須（`claude-sonnet-5` 単体は404）。

**環境変数**（サーバー専用・`VITE_` 接頭辞は禁止。ハンドラ内で読む）：

| 変数                  | 用途                                                                                                                    |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `AI_GATEWAY_API_KEY`  | Gateway のキー。`.env` に設定済み                                                                                       |
| `AI_GATEWAY_BASE_URL` | 既定 `https://ai-gateway.vercel.sh`（末尾 `/v1` なし）。`https://api.anthropic.com` に切り替えれば Gateway を迂回できる |

**キャッシュ戦略**：プリセット3人分は `vp run generate:passport` でパイプライン出力を事前生成し `src/data/cache/` にコミット（再現性100%・APIキー不要・ネットワーク障害に耐える）。**各ステップの実測msも記録**し、画面2はその実測値で再生する（偽のプログレスバーではない）。プリセットと自由入力は同一の `Stream<PipelineEvent>` を流し、差し替わるのは Layer だけ。プリセットのライブ生成が失敗したらキャッシュを最初から再生し、自由入力は他人の経歴文にキャッシュが存在しないため決定論ロジックの説明文に退避する。いずれもバナーで明示する。
