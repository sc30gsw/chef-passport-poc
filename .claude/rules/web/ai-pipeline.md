# AI Pipeline

`@effect/ai@0.37.0` + `@effect/ai-anthropic@0.27.0`, routed through Vercel AI Gateway. No Vercel AI SDK (`ai`, `@ai-sdk/*`) and no `@tanstack/ai` — both duplicate the abstraction Effect already provides, and `@tanstack/ai` explicitly does not support AI Gateway.

## The deterministic / LLM boundary — the core rule

| Step                                            | Implementation                                                                  |
| ----------------------------------------------- | ------------------------------------------------------------------------------- |
| 1. Extract and structure skills                 | **LLM** — `generateObject` against an `effect/Schema`                           |
| 2. Visa eligibility                             | **Deterministic function** in `src/domain/` + LLM for the explanation text only |
| 3. Translate skills to local kitchen vocabulary | **LLM** — `generateObject`                                                      |
| 4. Job matching                                 | **Deterministic score** in `src/domain/` + LLM for the reason text only         |

**Judgement is deterministic; only the wording is generated.** Never move a scoring or eligibility decision into a prompt — it is the project's central design claim and what the tests prove.

```typescript
// CORRECT: score first, then ask for prose about the result
const explain = Effect.gen(function* () {
  const score = scoreJobMatch(skills, job);
  const reason = yield* LanguageModel.generateObject({
    objectName: "reason",
    prompt: reasonPrompt(job, score),
    schema: MatchReason,
  });
  return { reason: reason.value, score };
});

// WRONG: the model decides the score
const graded = Effect.gen(function* () {
  return yield* LanguageModel.generateObject({
    prompt: "Score these 15 jobs 0-100",
    schema: ScoredJobs,
  });
});
```

Hard constraints (sponsorship unavailable, age over the cap, salary below the visa floor) **exclude** rather than subtract, and the exclusion reason is shown in the UI. That display is the visible proof the logic exists.

## API surface

```typescript
import { LanguageModel } from "@effect/ai";
import { AnthropicClient, AnthropicLanguageModel } from "@effect/ai-anthropic";
import { FetchHttpClient } from "@effect/platform";
import { Config, Layer } from "effect";

const client = AnthropicClient.layerConfig({
  apiKey: Config.redacted("AI_GATEWAY_API_KEY"),
  apiUrl: Config.succeed("https://ai-gateway.vercel.sh"), // no trailing /v1
});
const AnthropicLive = Layer.provide(client, FetchHttpClient.layer);
const model = AnthropicLanguageModel.model("anthropic/claude-haiku-4.5");
```

- Module is `LanguageModel` — `AiLanguageModel` and `Completions` are removed
- `generateObject` returns the parsed value in `.value`
- `streamText` returns `Stream.Stream<Response.StreamPart>`; discriminate on `part.type`
- Serverless uses `FetchHttpClient.layer`, not `@effect/platform-node`

## AI Gateway routing

The gateway exposes an **Anthropic-compatible `/v1/messages`**, so `apiUrl` is the only change — no provider swap.

- **Model slugs are provider-prefixed and required**: `anthropic/claude-haiku-4.5`, `anthropic/claude-sonnet-5`. A bare `claude-sonnet-5` returns 404
- **No Claude model is free-tier eligible** — paid gateway credits are required
- Model split: `claude-haiku-4.5` for extraction and translation, `claude-sonnet-5` for explanation text (cheaper than sonnet-4.5, at $2/$10 per 1M)
- Keep `apiUrl` behind an env var so a direct `https://api.anthropic.com` run stays possible when the gateway is unavailable

Gateway-level fallback works on `/v1/messages` via a top-level `providerOptions.gateway` body field. It is absent from the Anthropic SDK schema (Vercel's own docs use `@ts-expect-error`), so injecting it through `@effect/ai-anthropic` needs a documented escape hatch — isolate that cast in one place.

```json
{ "providerOptions": { "gateway": { "models": ["anthropic/claude-haiku-4.5"] } } }
```

The response's `providerMetadata.modelAttempts[]` records each attempt. Retries are **not** a documented gateway feature — write them with `Effect.retry`.

## Committed cache

Preset personas run from JSON committed under `src/data/cache/`, generated by `scripts/generate-passport.ts` (`vp run generate:passport`). This makes the demo reproducible, API-key-free, and immune to network failure.

- The generator is committed and re-runnable — it is the evidence the pipeline actually runs
- Cache files are generated artifacts: never hand-edit them. Fix the generator and re-run
- A contract test decodes every cache file against current schemas. See [../typescript/effect-schema.md](../typescript/effect-schema.md)

## One Stream interface, two sources

Preset replay and live generation expose the **same** `Stream<PipelineEvent>`; only the Layer differs (`PipelineFromCache` vs `PipelineLive`). Do not fork the UI on which source is active — the timeline component consumes one type either way, and a client-side replay fallback exists for when streaming fails in production.

## Prompts

Prompts live next to their step in `src/features/passport/api/steps/`, as plain exported functions returning a string. No prompt strings inline in components, and no prompt assembled from unvalidated user input — the free-input resume is schema-validated and length-capped first.
